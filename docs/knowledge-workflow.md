# 知识积累与复用流程

本流程适用于有实际探索、测试或问题分析的工作。目标是让下一次相关任务能找到并复用已有认识，同时避免把一次观察、模型自述或推断当成永久规则。

## 1. 开始前检索

按对象、工具、环境、错误信息或功能场景检索 `docs/project.md`、`docs/knowledge.md`、`tasks/`、`tests/` 和 `.agents/skills/`；有相关旧 Run 时，在授权范围内查其摘要。记录本次复用的资料、适用条件和仍需现场核验的内容。环境、配置、版本、权限和能力清单可能变化，历史结论不能直接代替本次验证。

## 2. 工作中记录

围绕任务收集实际观察、来源与限制。区分权威规则、实测事实、代码观察、模型自述、推断和缺失证据；记录环境、版本或配置、时间及证据定位方式。工具可见不等于已经执行，也不等于所有 Agent 或环境都有此工具。原始日志和对话保存在本机 Run，遵守敏感信息及访问边界。

## 3. 结束时形成候选

Agent 主动判断哪些发现可供其他任务复用。正式 Run 将候选记录到 `artifacts/知识沉淀候选.md`，在 `result.md` 链接；无需正式 Run 的探索可在 `.runtime/scratch/` 就近记录。有无新发现都在结果中说明；没有候选时写“无”，不创建空候选或臆造结论。

对每个候选按下列格式记录，写脱敏摘要而非复制原始内容：

```markdown
## 候选：<主题>
- 状态：待验证／待确认／已采纳／不采纳；记录日期与时区：
- 观察或来源事实：
- 分析推断及证据缺口：
- 适用范围：环境、版本或配置、账号角色及限制（未知项写未知）：
- 证据：Run 相对路径、文件和可定位的记录；共享时另给脱敏摘要或受控归档引用：
- 已有资产核对：检索位置、相关条目和结论（已覆盖／补充更新／新增／冲突／依据不足）：
- 建议目标：docs/project.md（权威事实入口）／docs/knowledge.md（已确认经验）／相关 skill（可复用方法）／tasks 或 tests（稳定资产）／继续留在 Run；写明具体修改建议：
- 后续动作：验证方式、需确认内容或失效条件：
```

如果发现冲突，保留双方依据和适用条件，不静默覆盖。若已有条目足够覆盖，引用它并记录本次是否需要复核，不重复新增知识。无证据或只有模型自述时保留为待验证线索。

## 4. 确认、更新、再次使用

向工程师展示候选、依据、拟修改位置和待确认事项；获得确认或已有明确的资产修改授权后，将适合共享且已脱敏的内容归入对应长期资产。事实和经验必须标明来源、验证状态、适用条件、核对日期和复核提示；需要共享的关键证据另存受控位置，本机 Run 路径不能作为团队唯一可访问的依据。技能只固化可复用操作方法，不把一次运行结果写成通用规则。更新后记录采纳与目标，按工作区规则人工评审 Git 变更。

后续同类任务先检索这些资产，以当前环境、版本和授权核对；发现变化时回到候选流程，保留历史依据，提出修订或失效建议。任务执行期间的 Agent 负责触发本流程；当前没有后台监听、自动发现所有历史 Run、自动审批或自动提交功能。
