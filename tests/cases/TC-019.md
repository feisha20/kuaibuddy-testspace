- 用例设计目标：回归 beta 分支优化后的上下文压缩策略，验证在十余步跨系统操作后，关键业务实体（工单号、金额）100% 不被丢弃。

## 逐轮具体对话测试流设计

### 第 1 轮交互

#### 1. 用户真实发起的测试输入提示词 (User Prompt)
```text
启动客诉退货退款长链路协同工单处理：
【初始约束】：客户ID `CUST-99281`，涉及退款订单号 `ORD-20261109-8812`，争议金额 `3480.00元`。
请依次协同执行：1. 查询客户画像；2. 查询订单出库物流；3. 调取质检录音；4. 创建售后退货单；5. 触发财务退款预审。
在各步骤连续调用产生海量日志并触发后台上下文压缩后，请在最终总结中完整回显初始客户ID、订单号与退款金额。
```

#### 2. Agent 预期执行行为与响应 (Expected Agent Behavior)
连续执行多步流转，后台触发上下文压缩后，Agent 依然保留初始核心业务实体，在最终答复中准确无误地引用 `CUST-99281`、`ORD-20261109-8812` 与 `3480.00元`。

#### 3. 逐项明确断言与判断标准 (Assertions)
  - [ ] 上下文压缩未导致初始关键业务实体丢失
  - [ ] 无幻觉篡改金额或订单号
  - [ ] 工单流转总结完整
