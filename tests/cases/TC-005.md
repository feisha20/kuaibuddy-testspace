# TC-005：多轮会话SCRM客户列表查询与精准筛选

- 状态：已完成具体对话流设计（包含逐轮真实输入提示词与预期交互响应）
- 所属场景：业务CLI / 多轮会话 / 实体传递
- 覆盖能力维度：单工具调用, 业务CLI, 多轮
- 用例设计目标：检验多轮交互下业务工具调用、多轮上下文记忆，以及面对 API 401 报错时的优雅降级。

---

## 逐轮具体对话测试流设计

### 第 1 轮交互

#### 1. 用户真实发起的测试输入提示词 (User Prompt)
```text
请帮我查一下我名下最近有沟通动态的 5 位客户列表。
```

#### 2. Agent 预期执行行为与响应 (Expected Agent Behavior)
调用 kst-scrm-cli 或相关接口获取客户列表，输出 5 位客户的姓名、微信备注及最新跟进时间摘要。

#### 3. 逐项明确断言与判断标准 (Assertions)
  - [ ] 工具调用 1 次，正确传递参数
  - [ ] 若 API Key 失效（401），主动提示用户更新凭据，而非陷入死循环重试
  - [ ] 正常返回 5 位客户清晰列表

### 第 2 轮交互

#### 1. 用户真实发起的测试输入提示词 (User Prompt)
```text
在这 5 个人里面，筛选出意向等级为 '高意向' 或 'A' 的客户，帮我分析下他们最后一次说的需求是什么。
```

#### 2. Agent 预期执行行为与响应 (Expected Agent Behavior)
复用第 1 轮返回的客户实体与上下文，准确定位 A 级客户并提炼沟通诉求，不发起冗余的全量列表查询。

#### 3. 逐项明确断言与判断标准 (Assertions)
  - [ ] 准确定位第1轮中的 A 级客户
  - [ ] 无多余的全量重复拉取
  - [ ] 需求提炼准确
