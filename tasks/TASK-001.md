# TASK-001：KuaiBuddy 基础对话回归

> 任务定义草案：正式需求、环境、权限和具体断言尚待补齐。本文件不代表已授权发送对话或已执行测试。

## 目标
以正式需求为依据，复用固定场景验证基础对话及多轮上下文行为，记录可追溯结果。

## 范围
- 包含：已明确预期的单轮输入、同一会话的后续追问及响应记录。
- 排除：生产写入、批量压测、未授权工具调用、自动创建外部缺陷，以及用户未主动要求的浏览器 UI 测试。

## 前置条件
- 确认目标环境、被测版本、所选 Agent／配置、测试账号角色及对话执行授权。
- 确认正式需求、测试输入、可核对的预期结果与允许调用的工具范围。
- 确认可用执行方式及配额、费用、数据保留和清理要求。
- 若使用浏览器，用户已主动要求浏览器测试；否则采用获授权的已有工具或记录缺失。

## 推荐步骤
1. 检索规则和已有资产，补齐或标记前置条件缺口。
2. 新建 Run，记录本次用例、数据、版本、执行方式及范围。
3. 在已授权环境执行单轮及多轮场景；逐轮等待响应完成后再发送下一轮。
4. 记录真实返回、可获取的关联标识、完成状态和证据；缺失字段明确标注未获取。
5. 按正式规则核对结果，区分事实、推断和证据不足。
6. 整理 result.md，列出失败、阻塞及资产完善建议。

## 验收标准
- 执行完成：计划内场景都有明确状态、观察与证据，或明确阻塞／未执行原因，三个 Run 文件完整。
- 业务通过：所有必测场景满足正式验收依据且无失败或阻塞；前置资料未补齐时不得认定业务通过。
- 相同任务再次执行创建新 Run，旧结果和任务定义不被覆盖。

## 风险与注意事项
- 对话可能触发外部工具、消耗配额或保留内容，执行前按场景确认允许范围。
- 不提交真实会话内容、凭据和用户信息；敏感证据须脱敏并按团队规定归档。
