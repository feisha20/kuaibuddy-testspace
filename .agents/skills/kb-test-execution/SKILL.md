# KuaiBuddy 本地任务执行

按仓库 AGENTS.md 读取相关项目事实、知识、任务和用例。本技能组织运行记录，不实现登录或接口客户端；按实际可用性选择获授权工具，缺少工具时报告缺口。

1. 核实环境、版本、角色、正式预期和允许操作范围。缺失前置条件的用例标记阻塞，继续可独立工作。
2. 按 README.md 创建独立 Run：UTC 时间戳加随机后缀，创建时禁止覆盖。复制 assets/ 下三个模板，替换 TASK_ID 和 RUN_ID。
3. 当本次已授权使用禅道跟踪时，执行前检查关联工作任务、测试单、构建、用例版本与负责人；按用户指定方式启动任务，确认默认剩余工时为 2 小时时可使用该值，不虚构已消耗工时。按需将用例关联至正确测试单；不为单次探索强制创建禅道对象。
4. 在 plan.md 记录范围、依据、数据、版本、工作树状态和任务差异；execution.md 只记录真实动作及时间，不预填成功。
5. 对话逐轮等待完成，保存真实响应和实际可获取的关联标识；接口按正式契约核对响应及业务副作用。未获取字段明确标注，不能编造。开始与结束时间在真实操作发生时记录；原始时间缺失时不能用文件时间或提交时间代替。
6. result.md 分别统计通过、失败、阻塞、未执行，逐项列出依据与证据，推断标为待验证。创建 Run 或命令退出成功不等于业务通过。
7. 在已授权回写禅道时，按真实步骤及含时区的原始起止时间提交结果，回读核对；非 JSON 或不确定响应先查远端并按原操作防重，不重发。完成任务前按用户确认的实际工时处理，核查父任务和其余任务状态；完成后回读并报告联动。用户要求逐项确认时，每项开始前等待确认。
8. 提出资产沉淀建议，工程师确认前不将运行观察写成项目知识；已有明确资产更新授权时按范围执行。

## 模板与交付
- [计划模板](assets/plan.md)：本次范围和前置条件。
- [执行模板](assets/execution.md)：实际动作和证据索引。
- [结果模板](assets/result.md)：真实结果与限制。
- 脱敏日志保存至 logs/，获授权截图至 screenshots/，报告和其他产物至 artifacts/。
- 交付 TASK_ID、RUN_ID、结果路径及主要限制。不自动上传证据、提交 Git、清理历史 Run 或启动浏览器。
