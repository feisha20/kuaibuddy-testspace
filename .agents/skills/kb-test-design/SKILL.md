# KuaiBuddy 测试资产设计

先按仓库 AGENTS.md 读取项目事实、知识及相关任务和测试资产，优先复用已有目标、编号和依据。本技能只组织测试设计，不替代测试执行或授予外部操作权限。

## 设计流程

1. 确定用户目标、环境、被测版本和测试范围；分别标注来源事实、代码观察、推断和待确认项。模板、示例与模型推测不是业务规则。
2. 用户要求页面测试时，先查阅可靠的交互资料；需要探索实际页面且已获浏览器授权时再进行探索，未授权不启动浏览器。按实际页面操作与用户可见结果设计页面用例；接口事件、模型标识和日志用于辅助诊断，不擅自当成页面操作或验收条件。用例和禅道任务命名使用业务对象加具体场景，例如“【单轮对话】新建任务并发送消息”，内部编号用于追踪而非替代业务名称。
3. 将变更或需求映射到可观察的风险和场景，根据实际影响选择正向、异常、边界、历史兼容、权限隔离和状态一致性覆盖。对依赖特定配置的能力，先标明启用条件，不把框架提供能力等同于产品已使用。
4. 用户需要逐项执行清单时，将工作拆成可独立选择和追踪的条目，给出稳定的清单内编号、优先级、前置条件、具体操作、可核对的检查点及必要证据；标明依赖和建议顺序。缺少业务依据时将预期标为待确认，不编造成正式验收标准。
5. 在清单中说明后续执行如何引用编号、创建独立 Run、记录真实动作与通过／失败／阻塞／未执行结果；能力未启用或缺少工具时说明适用条件和阻塞原因。不要在清单中预填执行成功或把工具调用成功等同业务通过。
6. 覆盖矩阵、一次性计划和草稿放当前 Run 的 artifacts/ 或 `.runtime/scratch/`；可复用长期任务和用例按仓库模板与资产管理规则处理。用户明确要求创建或修改长期资产时，按授权实施；否则建议沉淀，经确认再更新。
7. 设计涉及实际探索时，按 [知识积累流程](../../../docs/knowledge-workflow.md) 记录可复用候选；纯设计没有新观察时无需臆造。交付时说明复用资产、覆盖范围、关键依赖与缺口；需要运行时使用 `kb-test-execution` 和对应环境技能，按实际用户授权执行。

本技能不自动连接环境、启动浏览器、创建禅道对象或执行测试；按需使用已有工具并遵守项目安全边界。
